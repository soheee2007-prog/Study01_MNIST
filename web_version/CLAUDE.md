# CLAUDE.md (web_version)

`desktop_version/`과 같은 CNN 모델을 브라우저에서 순수 자바스크립트로 추론하는 정적 사이트입니다. 루트의 `CLAUDE.md`(두 버전 공통 규칙)를 먼저 읽으세요.

## 외부 라이브러리 금지

실행 시 외부 라이브러리·CDN·npm·번들러를 쓰지 않습니다. 모든 계산(합성곱, 전처리 등)은 이 폴더의 JS 파일 안에서 직접 구현합니다. 검증에 쓰는 도구(파이썬, `python -m http.server`, 헤드리스 브라우저)는 개발용이며 배포물에 포함되지 않습니다.

## 파일 구성

| 파일 | 역할 | export |
|---|---|---|
| `index.html` | 모듈 진입점(`<script type="module" src="앱.js">`), `file://`로 열었을 때의 안내문 포함 | - |
| `스타일.css` | 화면 배치(넓은 화면은 좌우, 600px 미만은 위아래, 가로 스크롤 없음) | - |
| `그림판.js` | 280×280 캔버스에 Pointer Events로 그리기, 회색조 픽셀 추출 | `class 그림판` |
| `앱.js` | 모델 로딩, 그리기 종료 시 인식, 결과·확신도·상위 3개 후보·확률 막대 표시 | (진입점, export 없음) |
| `모델.js` | 순전파(합성곱·ReLU·최대풀링·완전연결·소프트맥스)와 가중치 로딩 | `합성곱3x3`, `렐루`, `최대풀링2`, `완전연결`, `소프트맥스`, `async 모델_불러오기` |
| `전처리.js` | `app.py`의 `전처리()`를 그대로 재현 | `전처리`, `란초스_축소` |
| `검증.html` | 로컬 검증 페이지(아래 참고) | - |
| `가중치.bin`, `가중치정보.json` | `desktop_version/가중치내보내기.py`가 생성, 깃에 커밋됨 | - |
| `검증데이터.json` | `desktop_version/검증데이터만들기.py`가 생성, **깃에 넣지 않음**(아래 참고) | - |

## 로컬 실행

`file://`로 직접 열면 ES 모듈과 `fetch`가 CORS에 막혀 조용히 멈춥니다(`index.html`의 안내문이 이 경우에만 보입니다). 반드시 정적 서버로 여세요.

```bash
cd web_version
python -m http.server 8000
# http://localhost:8000 으로 접속
```

## 가중치 파일 형식

- `가중치.bin`: float32 little-endian 숫자를 이어 붙인 순수 데이터, 정확히 **1,871,272바이트**(467,818개 값)
- `가중치정보.json`: 텐서 **12개**(합성곱 4개 + 완전연결 2개의 weight/bias)의 이름·형상·시작 위치·개수, 그리고 정규화 상수 `평균`(0.1307)·`표준편차`(0.3081)
  - 순서: `합성곱1` → `합성곱2` → `합성곱3` → `합성곱4` → `완전연결1`[128,3136] → `완전연결2`[10,128] (각각 가중치 다음 편향)
  - BatchNorm은 학습 시점에 앞 합성곱에 이미 합쳐져 있어 JS에는 등장하지 않음
- `모델_불러오기`는 `.bin` 크기가 기대값과 다르면 한국어 오류를 던집니다. 정규화 상수는 이 파일에서 읽고 JS 코드에 직접 적지 않습니다(값의 출처를 `desktop_version/model.py` 하나로 유지하기 위함).

## 파이썬과 맞춰야 할 지점

`전처리.js`는 `app.py`의 `전처리()`를 단계와 반올림 방식까지 그대로 옮긴 것입니다. 한쪽만 고치면 두 버전이 다른 답을 냅니다.

- 전처리 6단계(반전 → bbox → 20으로 축소 → LANCZOS 축소 → 28×28 가운데 배치 → 무게중심 이동·정규화)의 순서
- 긴 쪽을 20으로 줄이는 `round`는 파이썬처럼 **짝수 반올림**(banker's rounding)
- LANCZOS(a=3) 축소는 PIL의 정수 고정소수점 계산(`PRECISION_BITS = 22`)을 재현하고, 단계마다 0~255 정수로 반올림·범위를 잘라냄. 크기가 같은 방향은 처리를 생략하고, Pillow 12.3은 세로가 가로의 100배를 넘고 세로를 줄일 때 세로를 먼저 처리하는데 이 분기도 재현함 — **Pillow 버전이 바뀌면 다시 확인 필요**
- 그림판 붓 두께 20(`app.py`의 그리기와 같음)

## 검증 절차

```bash
# 1) desktop_version에서 정답 데이터를 먼저 만듦(없으면 검증.html이 실패로 처리)
cd desktop_version && python 검증데이터만들기.py

# 2) 정적 서버로 web_version을 연 뒤 검증.html을 엶
cd web_version && python -m http.server 8000
# 브라우저(또는 헤드리스)로 http://localhost:8000/검증.html 접속
```

성공하면 `document.title`이 `검증 통과 N/N`이 됩니다(현재 검사 14개, 실측 `검증 통과 14/14`). 실패하면 `검증 실패 K/N`이고 결과 표(`<table id="결과">`)에 항목별 실측값이 나옵니다.

| 항목(성공 기준) | 기준 | 실측 |
|---|---|---|
| 순전파 일치 | 확률 최대 절대차 ≤ 1e-4 | 2.8e-7(200장) |
| 전체 정확도 | 200장 중 97% 이상 | JS 100.0%(200/200), 파이썬 100.0% |

나머지 검사(가중치 파일 형식, 전처리 단독 비교, 빈 그림, 경계 표본, 그린 표본 30장 등)는 성공 기준이 아니라 원인을 좁히기 위한 보조 검사입니다.

`검증데이터.json`은 약 25~27MB(그림이 대부분)라 `.gitignore`에 들어 있고 깃에 커밋하지 않습니다. 저장소에 없으므로 GitHub Pages에도 올라가지 않고, 검증 페이지는 로컬 전용입니다.

## 배포

`main`에 push되면 `.github/workflows/pages.yml`(GitHub Actions)이 이 폴더(`web_version/`)만 GitHub Pages에 올립니다. 저장소 Settings → Pages → Source를 "GitHub Actions"로 한 번 설정해야 동작합니다. 모든 경로가 상대 경로라 `https://soheee2007-prog.github.io/Study01_MNIST/` 같은 하위 경로에서도 그대로 동작합니다.
