> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기존 PyTorch 데스크톱 앱을 `desktop_version/`으로 옮기고, 같은 가중치를 외부 라이브러리 없는 순수 자바스크립트로 추론하는 정적 웹 앱 `web_version/`을 만든다.

**Architecture:** 파이썬 스크립트 2개(`desktop_version/`)가 BatchNorm을 합친 가중치(`가중치.bin` + `가중치정보.json`)와 정답 데이터(`검증데이터.json`)를 `web_version/`에 쓴다. 웹은 ES 모듈 4개(`모델.js`, `전처리.js`, `그림판.js`, `앱.js`)로 구성하고, `검증.html`이 JS 결과를 파이썬 결과와 대조한다.

**Tech Stack:** Python 3.13, PyTorch 2.14(CPU), Pillow 12.3, numpy / 브라우저 표준 JS(ES 모듈, fetch, Canvas, Pointer Events) / 검증 실행은 `python -m http.server` + 헤드리스 Edge / GitHub Actions(Pages)

**Spec:** `docs/superpowers/specs/2026-09-22-web-desktop-split-design.md`

## Review Focus

1. **어중간한 크기와 부드러운 획 가장자리.** MNIST를 정확히 10배 키운 그림만 쓰면 bbox가 항상 10의 배수다. 이 경우 확대 경로, 은행가 반올림 경계, 안티에일리어싱 회색 값, 캔버스 가장자리에 닿은 획이 한 번도 검사되지 않는다. 그래서 태스크 3이 `app.py`의 그리기 방식으로 PIL에 획을 그린 **그린 표본 30장**을 추가하고, 태스크 5가 이 표본에 대해 JS와 파이썬 예측이 30/30 일치하는지 검사한다.
2. **부동소수점 인덱스 경계.** `19 * (21/19) = 21.000000000000004`처럼 곱셈 결과가 정수를 살짝 넘어 배열 밖을 읽을 수 있다. LANCZOS 계수 구간은 PIL처럼 `xmax`를 입력 길이로 잘라 막는다. 태스크 5는 1~280 모든 입력 길이에서 20으로 줄이는 경우와 1~19에서 늘리는 경우를 검사한다.
3. **깨진 가중치 파일.** `.bin` 길이가 4의 배수가 아니거나 기대 크기와 다르면 `new Float32Array()`가 네이티브 RangeError를 던진다. 이를 막기 위해 `모델_불러오기`가 먼저 검사해 한국어 오류를 던지게 한다(태스크 4).
4. **로딩 중에 그린 그림.** 모델 적재가 끝나기 전에 그린 그림은 적재가 끝나면 자동으로 인식되어야 한다(태스크 6).
5. **`file://`로 연 경우.** 모듈이 CORS에 막혀 화면이 조용히 멈춘다. 그래서 `index.html`에 모듈 없이 동작하는 안내문을 두고, 앱이 시작되면 숨긴다(태스크 6).

**Interfaces:**
- Consumes: `desktop_version/model.py`의 `숫자인식CNN`, `가중치_파일`, `평균`, `표준편차`
- Produces: `가중치정보.json` 형식 `{"형식": "float32-le", "평균": 0.1307, "표준편차": 0.3081, "텐서": [{"이름", "형상", "시작", "개수"}, ...]}`. `시작`과 `개수`는 float 개수 단위다. 텐서 12개는 Global Constraints의 순서를 따르고, `가중치.bin`에 그 순서대로 이어 붙인다.

이 태스크의 검사는 스크립트 안의 자체 검증이다. 합친 가중치로 순수 numpy 순전파를 한 결과가 PyTorch `eval()` 출력과 같아야 저장한다. numpy 순전파는 JS가 할 계산(합성곱 패딩 1 → ReLU → 풀링 …)을 그대로 흉내 내므로, 텐서 순서·형상·BN 합치기 오류를 여기서 잡는다.

- [ ] **Step 1: 스크립트 작성**

```python
# -*- coding: utf-8 -*-
"""
학습된 가중치(mnist_cnn.pt)를 웹 버전이 읽을 수 있는 파일 2개로 내보냅니다.
  - ../web_version/가중치.bin        : float32 little-endian 숫자를 이어 붙인 데이터
  - ../web_version/가중치정보.json   : 텐서 이름·형상·위치와 정규화 상수
BatchNorm은 앞의 합성곱에 미리 합쳐서, 웹은 합성곱·ReLU·풀링·완전연결만 계산하면 됩니다.
실행 방법: desktop_version 폴더에서 python 가중치내보내기.py
"""
import json
import os
import sys

import numpy as np
import torch

from model import 숫자인식CNN, 가중치_파일, 평균, 표준편차

웹_폴더 = os.path.join(os.path.dirname(os.path.abspath(__file__)), "..", "web_version")
허용_오차 = 1e-4


def 배치정규화_합치기(합성곱, 배치정규화):
    """합성곱 뒤의 BatchNorm을 합성곱 가중치·편향에 합쳐 (가중치, 편향) numpy 배열로 돌려줍니다."""
    배율 = 배치정규화.weight / torch.sqrt(배치정규화.running_var + 배치정규화.eps)
    가중치 = 합성곱.weight * 배율.reshape(-1, 1, 1, 1)
    편향 = (합성곱.bias - 배치정규화.running_mean) * 배율 + 배치정규화.bias
    return 가중치.detach().numpy().astype(np.float32), 편향.detach().numpy().astype(np.float32)


def 텐서_목록_만들기(모델):
    """(이름, numpy 배열) 12개를 웹이 읽을 순서대로 돌려줍니다."""
    특징 = 모델.특징추출
    목록 = []
    for 번호, (합성곱_위치, 정규화_위치) in enumerate([(0, 1), (3, 4), (7, 8), (10, 11)], start=1):
        가중치, 편향 = 배치정규화_합치기(특징[합성곱_위치], 특징[정규화_위치])
        목록 += [(f"합성곱{번호}.가중치", 가중치), (f"합성곱{번호}.편향", 편향)]
    for 번호, 위치 in enumerate([1, 4], start=1):
        층 = 모델.분류[위치]
        목록 += [(f"완전연결{번호}.가중치", 층.weight.detach().numpy().astype(np.float32)),
                 (f"완전연결{번호}.편향", 층.bias.detach().numpy().astype(np.float32))]
    return 목록


def 넘파이_순전파(텐서, 입력):
    """합친 가중치만으로 웹과 같은 순서의 계산을 합니다. 입력: (N,1,28,28) → 출력: (N,10) 점수"""
    값 = dict(텐서)
    x = torch.from_numpy(입력)
    for 번호 in range(1, 5):
        x = torch.nn.functional.conv2d(x, torch.from_numpy(값[f"합성곱{번호}.가중치"]),
                                       torch.from_numpy(값[f"합성곱{번호}.편향"]), padding=1).clamp_min(0)
        if 번호 in (2, 4):
            x = torch.nn.functional.max_pool2d(x, 2)
    x = x.flatten(1)
    x = (x @ torch.from_numpy(값["완전연결1.가중치"]).T + torch.from_numpy(값["완전연결1.편향"])).clamp_min(0)
    x = x @ torch.from_numpy(값["완전연결2.가중치"]).T + torch.from_numpy(값["완전연결2.편향"])
    return x.numpy()


def 메인():
    모델 = 숫자인식CNN()
    모델.load_state_dict(torch.load(가중치_파일, map_location="cpu", weights_only=True))
    모델.eval()
    텐서 = 텐서_목록_만들기(모델)

    # 저장하기 전에 합친 가중치가 원래 모델과 같은 답을 내는지 확인합니다.
    생성기 = torch.Generator().manual_seed(0)
    시험_입력 = torch.randn(8, 1, 28, 28, generator=생성기)
    with torch.no_grad():
        기대 = 모델(시험_입력).numpy()
    실제 = 넘파이_순전파(텐서, 시험_입력.numpy())
    최대_차이 = float(np.abs(기대 - 실제).max())
    print(f"합친 모델과 원래 모델의 최대 차이: {최대_차이:.3e}")
    if 최대_차이 > 허용_오차:
        print(f"차이가 허용 오차 {허용_오차}를 넘어 저장하지 않습니다.")
        sys.exit(1)

    os.makedirs(웹_폴더, exist_ok=True)
    정보 = {"형식": "float32-le", "평균": 평균, "표준편차": 표준편차, "텐서": []}
    시작 = 0
    with open(os.path.join(웹_폴더, "가중치.bin"), "wb") as 파일:
        for 이름, 배열 in 텐서:
            파일.write(배열.astype("<f4").tobytes())
            정보["텐서"].append({"이름": 이름, "형상": list(배열.shape), "시작": 시작, "개수": int(배열.size)})
            시작 += int(배열.size)
```

### Task 3: 검증 데이터 만들기

**Files:**
- Create: `desktop_version/검증데이터만들기.py`
- Modify: `.gitignore` (`web_version/검증데이터.json` 추가)
- Create (생성물, 커밋 안 함): `web_version/검증데이터.json`

**Interfaces:**
- Consumes: `model.py`(`숫자인식CNN`, `가중치_파일`), `app.py`(`전처리`), `./data`의 MNIST 시험 세트
- Produces: `검증데이터.json`

```json
{
  "크기": 280,
  "MNIST": [ {"그림": "<base64, 280*280 uint8, 흰 바탕 255 / 검은 글씨 0>", "전처리": [784개 float], "확률": [10개 float], "정답": 7}, ... 200개 ],
  "그린표본": [ {"그림": "...", "전처리": [...], "확률": [...], "정답": 3, "설명": "숫자 3, 크기 0.63, 부드러운 가장자리"}, ... 30개 ],
  "경계표본": [ {"그림": "...", "전처리": [...], "확률": [...], "정답": -1, "설명": "25×40 사각형 (12.5 → 짝수 반올림 12)"}, ... 7개 ],
  "파이썬정확도": {"MNIST": 200, "그린표본": 27}
}
```

`경계표본`은 전처리 계산의 경계를 시험하는 도형입니다. 모두 280×280 흰 바탕에 검은 도형을 그리고, 정답은 없어서 `-1`로 둡니다.
- 25×40 사각형: 12.5가 짝수 반올림으로 12가 되는 경우
- 35×40 사각형: 17.5 → 18
- 40×25 사각형: 가로·세로 방향을 바꾼 경우
- 3×3 점: 20으로 확대하는 경우
- 1×40 선: 새 가로가 `max(1, round(0.5)) = 1`로 원래와 같아 가로 처리만 건너뛰는 경우
- 12×20 사각형: 긴 쪽이 이미 20이라 두 방향 모두 처리하지 않는 경우
- 280×280 전부 검은 그림: 전체 영역이 bbox인 경우

`전처리`는 `app.전처리(그림)`의 `(1,1,28,28)` 텐서를 펼친 784개 값(행 우선)이다. `확률`은 `softmax(모델(전처리))`이다. 숫자는 `round(x, 7)`로 저장한다.

### Task 4: 자바스크립트 순전파 (모델.js + 검증.html 모델 검사)

**Files:**

**Interfaces:**
- Consumes: `가중치.bin`, `가중치정보.json`(Task 2), `검증데이터.json`의 `MNIST[i].전처리`, `MNIST[i].확률`(Task 3)

  - `소프트맥스(점수: Float32Array) → Float32Array` — 최대값을 반복문으로 구함(`Math.max(...배열)` 금지)
