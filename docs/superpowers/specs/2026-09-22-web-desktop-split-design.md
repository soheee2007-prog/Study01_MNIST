# 웹 버전 / 데스크톱 버전 분리 설계

- 작성일: 2026-09-22
- 브랜치: `feature/web-desktop-split`

## 1. 목표

손글씨 숫자 인식 프로그램을 두 버전으로 나눈다.

| 버전 | 폴더 | 추론 방식 | 실행 환경 |
|---|---|---|---|
| 데스크톱 | `desktop_version/` | PyTorch (기존 코드 그대로) | 윈도우 + Python, tkinter 창 |
| 웹 | `web_version/` | **외부 라이브러리 없는 순수 자바스크립트** | 브라우저, GitHub Pages 정적 배포 |

**성공 기준**

1. `desktop_version/`에서 `python train.py`, `python app.py`가 이전과 똑같이 동작한다.
2. `web_version/`을 정적 서버로 열면 마우스·터치로 숫자를 그려 인식할 수 있다. 결과, 확신도, 0~9 확률 막대를 보여 준다.
3. 웹 추론 결과가 PyTorch와 일치한다. MNIST 시험 이미지의 logit 최대 오차는 1e-3 미만이고, 예측 숫자는 모두 같다.
4. 웹 전처리 결과가 데스크톱 `전처리()`와 사실상 일치한다. 정규화된 값의 최대 오차는 0.05 미만이고, 예측 숫자는 같다.
5. `main`에 push하면 GitHub Actions가 `web_version/`만 GitHub Pages에 배포한다.
6. 각 폴더에 그 폴더용 `CLAUDE.md`가 있다.

**하지 않는 것 (YAGNI)**

- 웹에서의 학습
- 모델 구조 변경이나 재학습
- 번들러, npm 패키지, 프레임워크

## 2. 폴더 구조

```
(루트)
├─ CLAUDE.md                 두 버전을 안내하는 개요로 다시 작성
├─ README.md                 두 버전 소개 + 웹 사용법 + 배포 방법
├─ .gitignore                data/, __pycache__ (위치와 상관없이 적용되는 기존 패턴 유지)
├─ .github/workflows/pages.yml
├─ docs/superpowers/         스펙과 구현 계획
├─ desktop_version/
│  ├─ CLAUDE.md              새로 작성
│  ├─ README.md              기존 README를 옮김 (git mv)
│  ├─ model.py  train.py  app.py  make_icon.py  icon.ico  mnist_cnn.pt   (git mv)
│  ├─ data/                  git에 포함되지 않으므로 일반 이동
│  ├─ 가중치내보내기.py      새로 작성: mnist_cnn.pt → web_version/가중치.json + 가중치.bin
│  └─ 검증데이터만들기.py    새로 작성: PyTorch 기준 정답 → web_version/검증데이터.json
└─ web_version/
   ├─ CLAUDE.md              새로 작성
   ├─ index.html             인식 화면
   ├─ 스타일.css
   ├─ 검증.html              브라우저에서 돌리는 검증(테스트) 페이지
   ├─ 그림판.js  전처리.js  모델.js  앱.js
   ├─ 가중치.json  가중치.bin   (가중치내보내기.py로 생성, 커밋함)
   └─ 검증데이터.json          (검증데이터만들기.py로 생성, 커밋함)
```

### 요청 목록과 실제 저장소의 차이 (결정 사항)

- 요청 목록의 `preprocess.py`는 저장소에 **없다**. 전처리 로직은 `app.py`의 `전처리()`에 있으므로 새 파일을 만들지 않고 `app.py`에 그대로 둔다.
- 요청 목록의 `손글씨인식.app`은 저장소에 **없다**. 바탕 화면의 "손글씨 숫자 인식" 바로가기(.lnk, 저장소 밖)만 있으므로, 이 바로가기의 대상 경로와 작업 폴더를 `desktop_version\`으로 고친다.
- 요청 목록에 없는 `make_icon.py`, `icon.ico`, `README.md`도 데스크톱 전용이므로 `desktop_version/`으로 옮긴다. 루트에는 새 개요 README를 둔다.
- `data/`는 `.gitignore` 대상이라 `git mv`를 쓸 수 없다. 일반 이동으로 옮긴다.
- 검증 페이지에 쓸 정답 자료 `검증데이터.json`은 `web_version/`에 둔다.

## 3. 가중치 형식

`가중치내보내기.py`는 `desktop_version/` 폴더에서 실행한다(기존 규칙: 상대 경로는 현재 작업 폴더 기준). 출력 위치는 스크립트 파일 기준 `../web_version/`이다.

- **BatchNorm을 앞의 합성곱에 합친다.**
  `배율 = γ / √(분산 + 1e-5)`
  `W' = W · 배율`
  `b' = (b − 평균) · 배율 + β`
  그래서 JS는 합성곱·ReLU·최대풀링·완전연결만 구현한다.
- **`가중치.bin`:** float32 little-endian 값을 이어 붙인 파일. 파라미터는 467,818개(BN을 합친 뒤 기준), 크기는 1,871,272바이트(약 1.87MB).
- **`가중치.json`:** 층 순서와 모양, 파일 안의 위치를 담는다.

```json
{
  "형식": "float32-le",
  "평균": 0.1307,
  "표준편차": 0.3081,
  "텐서": [
    {"이름": "합성곱1.가중치", "모양": [32, 1, 3, 3], "시작": 0, "개수": 288},
    {"이름": "합성곱1.편향", "모양": [32], "시작": 288, "개수": 32}
  ]
}
```

위는 앞부분만 보인 예시다. 텐서 순서는 합성곱1~4의 가중치·편향, 완전연결1의 가중치·편향 `[128, 3136]`, 완전연결2의 가중치·편향 `[10, 128]`이다. `시작`과 `개수`는 float 개수 단위다.

평균과 표준편차를 JSON에 넣어 두면 웹이 `model.py`와 같은 값을 쓴다는 사실을 파일 하나로 보장할 수 있다.

## 4. 웹 모듈 (ES 모듈, 한국어 이름)

| 파일 | 책임 | 공개 인터페이스 |
|---|---|---|
| `모델.js` | 순수 JS 신경망 연산과 가중치 불러오기 | `합성곱3x3(입력, 채널, 높이, 너비, 가중치, 편향, 출력채널) → Float32Array`, `렐루(배열)` (제자리 변환), `최대풀링2(입력, 채널, 높이, 너비) → Float32Array`, `완전연결(입력, 가중치, 편향, 출력수) → Float32Array`, `소프트맥스(logit) → Float32Array`, `async 모델_불러오기(경로 = ".") → { 추론(입력784) → logit(10), 평균, 표준편차 }` |
| `전처리.js` | 데스크톱 `전처리()`를 그대로 옮김 | `전처리(회색조, 가로, 세로, 평균, 표준편차) → Float32Array(784) \| null`. 빈 그림이면 `null`. 보조 함수 `란초스_축소(값, 가로, 세로, 새가로, 새세로)`도 테스트용으로 export |
| `그림판.js` | 캔버스 그리기(마우스·터치·펜) | `class 그림판 { constructor(캔버스, { 붓두께 = 20, 그리기끝 }) ; 회색조_가져오기() → Uint8ClampedArray ; 지우기() }` |
| `앱.js` | 화면 연결: 로딩 상태, 인식, 결과·막대 표시 | 없음 (index.html의 진입점) |

**전처리 세부 (데스크톱과 1:1 대응)**

1. 반전: `255 − 값`
2. bbox 계산: PIL `getbbox`와 같게 0이 아닌 픽셀 영역을 찾는다. 오른쪽·아래 경계는 포함하지 않는다.
3. 축소: 긴 쪽을 20으로 줄인다. 새 크기는 `max(1, round(가로·배율))`이며, 반올림은 Python과 같은 은행가 반올림(짝수 반올림)을 따른다.
4. 축소 방식: PIL LANCZOS(a=3) 알고리즘을 재현한다. 축소할 때 지지 폭을 배율만큼 넓히고, 가로 방향 → 세로 방향 순으로 처리하며, 각 단계 결과를 0~255 정수로 반올림·잘라낸다.
5. 28×28 바탕에 `((28−w)//2, (28−h)//2)` 위치로 붙인다.
6. 무게중심을 계산하고, 이동량 `round(14 − 중심)`만큼 정수 이동한다. 범위를 벗어난 곳은 0이다.
7. 정규화: `(값/255 − 평균) / 표준편차`

부동소수점 계산 차이로 픽셀 값이 ±1 정도 달라질 수 있어서 성공 기준 4의 허용 오차를 0.05로 둔다.

**그림판**

- Pointer Events로 마우스·터치·펜을 한 번에 처리한다.
- `touch-action: none`으로 그리는 동안 화면이 스크롤되지 않게 한다.
- 캔버스 내부 해상도는 항상 280×280이다. CSS로 화면 폭에 맞게 줄여 보여 주되, 포인터 좌표는 내부 해상도로 환산한다.
- 선은 검은색, 굵기 20, 둥근 끝이다.
- 오른쪽 클릭과 Delete 키로 지운다(데스크톱과 같음).

## 5. 오류 처리

- 가중치를 불러오지 못하면(fetch 실패, 크기 불일치) 결과 영역에 "모델을 불러오지 못했습니다" 안내를 보여 주고 그리기 입력을 받지 않는다.
- 모델 로딩 중에는 "모델 불러오는 중…"을 표시한다.
- 빈 캔버스는 인식하지 않는다(`전처리`가 `null`을 돌려줌).
- ES 모듈과 fetch를 쓰므로 `file://`로 열면 동작하지 않는다. 문서에는 `python -m http.server`로 확인하는 방법을 적는다.

## 6. 검증 (TDD)

- **`검증.html`:** 외부 라이브러리 없는 작은 테스트 러너다. 각 검사 결과를 목록으로 보여 주고, 끝나면 `document.title`을 `"검증 통과 N/N"` 또는 `"검증 실패 …"`로 바꾼다. 그래서 브라우저 도구로 자동 확인할 수 있다.
- **검사 항목**
  1. 연산 단위 검사: 작은 입력으로 손으로 계산한 값과 비교(합성곱 패딩, 풀링, 완전연결, 소프트맥스 합=1)
  2. 가중치 파일 검사: 텐서 개수와 모양, `.bin` 크기
  3. MNIST 시험 이미지 20장: PyTorch logit과의 최대 오차가 1e-3 미만이고 예측이 같음
  4. 합성 그림 5장(280×280, `app.py`와 같은 방식으로 PIL에 획을 그림): JS `전처리` 결과가 Python `전처리()`와 오차 0.05 미만이고 예측이 같음
  5. 빈 그림을 전처리하면 `null`
- **`검증데이터만들기.py`:** `desktop_version/`에서 실행한다. `model.py`와 `app.py`의 `전처리`를 가져다 써서 정답 자료를 만든다. 이미지는 uint8 base64, 기대값은 숫자 배열로 저장한다.
- 데스크톱 코드는 이동만 하므로 `python -c "import app"`으로 가져오기가 되는지, 그리고 가중치를 불러와 추론이 되는지 확인한다.

## 7. 배포

`.github/workflows/pages.yml`을 둔다.

- `main`에 push하거나 수동 실행(`workflow_dispatch`)하면 동작한다.
- `actions/configure-pages` → `actions/upload-pages-artifact`(`path: web_version`) → `actions/deploy-pages` 순으로 배포한다.
- 저장소 설정에서 Pages 소스를 "GitHub Actions"로 한 번 바꿔야 한다. 이 작업은 사용자가 직접 한다.
- 모든 경로는 상대 경로라서 `https://<사용자>.github.io/Study01_MNIST/` 같은 하위 경로에서도 동작한다.

- **루트:** 두 버전의 관계, 공통 계약(웹 가중치는 `desktop_version`에서 생성됨, 모델이나 정규화를 바꾸면 두 스크립트를 다시 실행), 폴더 안내
- **`desktop_version/CLAUDE.md`:** 기존 CLAUDE.md 내용 + 내보내기·검증 스크립트 + 실행 위치
- **`web_version/CLAUDE.md`:** 모듈 구조, 외부 라이브러리 금지, 로컬 실행·검증 방법, 전처리를 데스크톱과 맞추라는 주의, 배포

모든 이름·주석·메시지는 한국어로 쓴다(프로젝트 규칙).
